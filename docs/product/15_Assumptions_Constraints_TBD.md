## 2. Assumption 清单

| ID | 假设 | 推翻时影响 |
|---|---|---|
| A-001 | GCS 事先知道物理几何（地图/CAD/人工输入） | 若几何未知需实时感知 → 启用感知模块（未来） |
| A-002 | 第一阶段任务区地形平坦（相对参考点 ≈ 真高近似） | 若地形起伏 → 需绝对高程/感知 |
| A-003 | 高度参考系锚定在"计划中显式声明的参考点"（不随瞬时 EKF 原点漂移） | 若锚定失效 → 任务执行位置漂移 |
| A-004 | 速度/包线数值以 M400 量级为 benchmark 候选；Vehicle Definition 全量数值属 Assumption 层（DEC-051） | 若车辆定义不同 → 数值重算 |
| A-005 | 参考架次数值为候选，来源=项目负责人（抽象客户代表） | 真实客户/benchmark 确立后修订 |
| A-006 | 非起飞段航点高度的语义与低空安全性由 GCS 规划保证；FlightCore 不校验任务语义高度（除起飞段安全起飞高度，DEC-045） | 若规划保证失效 → 低空飞行风险需 FlightCore 侧额外防线（未来感知/包线，后置） |
| A-007 | **高级算法试验/落地解耦**：LQR/MPC/RL 实验第一阶段在 MIL/SIL 仿真进行（DEC-033），不要求实机；落地决策后置。硬件选型不因"试验计划"上调；架构保持"机载余量内 + 伴机接口"双路径 | 若某算法证明必须落地且超出机载余量 → 升级 MCU 或由伴机承担，FlightCore 接口不变 |
