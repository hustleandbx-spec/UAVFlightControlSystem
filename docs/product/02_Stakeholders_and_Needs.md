## 1. 利益相关方

| 干系人 | 角色 | 关注点 | 来源 |
|---|---|---|---|
| 操作者（Operator） | 受训设备操作人员：安全操作与应急处置有清晰认识；不关心/不需要了解内部算法实现；非飞控开发人员 | 安全、可控、明确结构化指令响应、监督与接管、HMI 可理解（任务级告警 + 标准处置流程） | DEC-003 |
| GCS 规划层（GCS Planner） | 任务规划与语义校验权威（任务语义层，FC 为场景无关执行者） | 航线规划能力（航点/动作/偏航/载荷朝向）、禁飞区规避、任务级配置；FC 不重复校验计划语义 | DEC-005 |
| 任务客户（Mission Customer） | 抽象 persona（巡检委托方，A-005）；载荷与任务 MOE 后置 | 巡检数据质量 / 任务有效性（第一阶段以"飞行执行代理"MOE 间接表达） | A-005, DEC-010 |
| 开发者（Developer） | 本项目负责人 / 飞控研制者 | 可演进架构、可验证性（MIL/SIL）、工程可落地、长期演进不被封死 | DEC-001, SYS-GOAL-07 |

## 2. 需要（Need）清单

> 需要 = 利益相关方"为什么需要这个系统"的陈述，来源 = Vision SYS-GOAL-01..07 + DEC；向下追溯到 MOE（§3）与 SYS-REQ（07）。

| SN | 需要 | 来源 | 支撑 MOE / 主要对应 |
|---|---|---|---|
| SN-001 | 操作者需要系统自主执行完整任务流程（起飞→出航→任务→返航→降落），全程仅需监督 | SYS-GOAL-01, DEC-019, MOE-A | MOE-A、MOE-C |
| SN-002 | 操作者需要任意阶段可介入控制（远程模式命令 / 直接接管飞行控制） | SYS-GOAL-01, DEC-019/023/110, MOE-C | MOE-C |
| SN-003 | 操作者需要系统始终受安全约束保护，且安全优先级 > 任务完成度与运行效率 | SYS-GOAL-02, DEC-004/028 | 安全门（非 MOE） |
| SN-004 | 操作者需要每条指令得到明确结构化响应（批准/拒绝/原因），支撑培训后的标准处置 | DEC-003/004/089/090 | MOE-C、安全门（命令审查） |
| SN-005 | 任务客户需要飞行品质支撑工业巡检（轨迹跟踪、位置保持、扰动抑制） | SYS-GOAL-03, DEC-010 | MOE-D、MOE-B（→ MOP 轨迹跟踪） |
| SN-006 | 任务客户/操作者需要出航效率与任务区精度分阶段权衡（非全程同一品质） | SYS-GOAL-04, DEC-010/054 | MOE-A、MOE-D |
| SN-007 | 操作者需要合法载荷变化不需针对每种载荷重新标定控制律 | SYS-GOAL-05 | MOE-D（→ SYS-GOAL-05 验证范围 / MOP） |
| SN-008 | 操作者需要能源不足时安全中断任务、保存进度、下架次可续接 | SYS-GOAL-06, DEC-037 | 安全门（能源）、MOE-A |
| SN-009 | 开发者需要架构保留向复合翼/倾转旋翼/GNSS-denied/高级自主演进的合理边界 | SYS-GOAL-07 | 非 MOE（架构演进） |
| SN-010 | 操作者需要以任务级告警 + 标准处置流程获取信息，不依赖内部算法知识 | DEC-003 | 非 MOE（HMI → SYS-REQ-012 后置 / 遥测） |
| SN-011 | GCS 规划层需要保有任务规划与语义校验权威（含禁飞区规避），FC 按预规划航线执行、不重复校验计划语义 | DEC-005/092/097/098 | 安全门（SYS-REQ-016 静态层） |

## 3. Need → MOE 映射

| MOE | 支撑的 SN |
|---|---|
| MOE-A 任务完成度（第一优先） | SN-001、SN-006、SN-008 |
| MOE-B 动作执行完整度 | SN-005、SN-001（动作分量） |
| MOE-C 自主性 | SN-001、SN-002、SN-004 |
| MOE-D 计划保真度 | SN-005、SN-006、SN-007 |
| 安全门（非 MOE，一票否决） | SN-003、SN-004、SN-008、SN-011 |
| 非 MOE（架构/HMI/GCS 层） | SN-009、SN-010、SN-011 |
