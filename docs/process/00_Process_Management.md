## 1. 本文件夹边界

- **只装过程文件**：决策（01）、风险（02）、问题（03）、评审门禁（04）+ 本说明。
- **不装任何需求、设计、开发内容**——那些在 `product/`（产品与技术链）。
- 判定：内容回答"**怎么定 / 怎么管 / 出过什么问题 / 门过了没有**"→ 本链；回答"**做什么 / 做成什么样 / 怎么验证**"→ product/。
- 特例：**01 会话·决策日志**保留各层产品原料原文（已拆分、标注"已拆分→product/xx"），目的是历史溯源，不构成当前权威——产品权威在 `product/`。

## 3. 边界规则：TBD / Assumption / Risk

三者易混，防漂移规则（15 §1/§2 与 02 共用）：

| 类 | 含义 | 处置 |
|---|---|---|
| **TBD** | 未定的决策（必须定） | 留在 product/15 §1，附待解来源 |
| **Assumption** | 暂依赖的陈述（假设为真） | 留在 product/15 §2，附推翻时影响 |
| **Risk** | 负向不确定性（概率 × 影响） | 入本链 02，附处置与状态 |

**转化规则**：
- TBD 长期不决 → 升为风险（先例：TBD-002 法规合规）；
- 假设可靠性存疑 → 记一条风险（先例：A-004 估算偏差 → R-01）；
- 风险缓解后残余 → 留"残余风险"字段。

## 4. 风险生命周期（个人项目三态）

```
跟踪中 ──风险事件发生──▶ 已触发 ──▶ 已缓解 / 已接受 / 已闭环
       （缓解动作完成）     （记录理由+兜底）  （不再构成风险）
```

处置 = **缓解**（有动作）/ **接受**（记录理由+兜底）/ **后置**（显式延后 + 触发条件）。不搞精确概率，分级即可。

## 5. 变更纪律（变更四问）

任何需求/设计/接口/参数变更，记录前必答：

1. **改了什么**（对象 + 内容）；
2. **为什么**（来源/驱动）；
3. **影响哪些需求·设计**（受影响 SYS-REQ / SUBSYS / 契约 / 文档）；
4. **是否需重验**（VER 是否失效 → 重跑范围）。

记录载体 = DEC 条目（01）+ 文档修订块；process/ 或 product/ 文件头部状态同步。

## 6. 铁律

1. **先登记后使用**：新编号前缀 / 缩写 / 工作包代号，先写入 00 §4 方可用于任何 SE 文档（00 §4.4）。
2. **每次访谈/会话收尾刷新本链**：01 追加「本次修订」+ DEC；02 风险状态更新；03 问题闭环；04 门禁过签。
3. **门禁前置**：进入下一阶段前检查 01 §12 SE 链矩阵无空白（DEC-080）。
