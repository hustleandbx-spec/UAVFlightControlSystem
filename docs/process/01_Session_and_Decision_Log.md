## 11. 功能分析（进行中，2026-08-06 启动）

> 📄 **已成文：** 拆分至 `product/08_System_Functional_Architecture.md` 与 `product/09_System_Logical_Architecture.md`。原文保留。

> 规则十一：先 Functional Analysis（功能分解），再定 Logical / Physical Architecture。本节省略功能推演过程，只记结论、模块方向与待澄清项。功能清单的每项须可追溯到 SYS-REQ/DEC。

**已确认：**

- **安全约束 = 横切直接否决层（DEC-057）**：非平行功能模块，对所有链直接否决。
- **命令审查 ≠ 安全否决（DEC-059）**：命令审查 = 程序/状态合法性（武装、飞行检查），属 Commander；安全否决 = FailSafe 模块（断链→悬停/迫降等事件式应急，横切）。
- **Commander = 统一命令门卫 + 飞控状态审查视图**（DEC-059）：持有任务/导航/状态估计等所有模块状态，命令审查时校验当前状态能否执行命令，通过才下发。
- **Commander 状态视图 = 模块权威 + 只读镜像（DEC-060）**：各模块回报状态，Commander 只能读、不能改；单一权威、无双源。
- **FailSafe = Commander 下级模块（DEC-060）**：经状态视图监控全部状态，出现异常即处置；处置机制挂起（TBD-014）。
- **MissionManager = 任务语义唯一权威；Navigator = 运动学合同执行器（DEC-061）**：Navigator 不解析任务语义，只执行"运动到哪里 + 以什么状态结束"的运动学合同；到达判据评估 + 段推进归 MissionManager。
- **Navigator 判据无感知（DEC-062）**：合同只含位置 + 设计终止状态（0.1m/速度归零），不含判据阈值；结果反馈（估计状态 vs 判据）到 MissionManager；Navigator→MissionManager 正常流无回报信号。
- **Navigator→FlightControl 轨迹参考 = 位置+速度+偏航（DEC-063）**：速度剖面由 Navigator 生成直传；不引入加速度前馈；偏航随轨迹一起传。
- **混合器 = FlightControl 内部子功能（DEC-064）**：不设独立 Mixer 模块，输出电机指令；矩阵参数走 Vehicle Definition；规则十二 = 数据解耦；执行链接口全闭合。
- **Navigator 持有当前状态（DEC-065）**：合同不含当前位置；轨迹 = 当前状态衔接 + 合同位置；StateEstimation→Navigator 状态流存在。
- **Commander = 统一 GCS 命令入口 + 审查批准 + 路由（DEC-066）**：命令集远大于正常流（加锁/解锁、查询、临时上传航点、载荷控制等），作用于多模块；命令/查询三通道模型已定。
- **五阶段 = 人为划分的过程视图，非实现状态机（DEC-067）**：MissionManager 进度 = 由计划位置派生的进度标签；包线/速度差异读航点参数 + Vehicle Definition，不读阶段。DEC-035 与 DEC-058 兼容。
- **术语定案（DEC-068）**：模块 Navigator 中文 = "制导"（=Vision Guidance）；MOP"导航精度"保留 = 状态估计误差。中文体系无歧义。
- **通信模块 = Gateway（纯传输层，MAVLink），日志/诊断 = 独立横切模块（DEC-069）**：功能分析模块补位完成。
- **航线直进 MissionManager，指令进 Commander（DEC-070/071）**：Gateway 按数据/指令分两路；临时上传航点=外部单步、内部两步（数据通道→MissionManager 校验 + 指令通道→Commander 激活），客户端无感知。
